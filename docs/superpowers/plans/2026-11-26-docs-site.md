# Documentation Site Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Starlight documentation site under `/shellwise/docs/`, with the landing page rewritten in Astro at `/shellwise/`, deployed by the existing Pages workflow.

**Architecture:** `site/` is one Astro project. Hand-written pages are Markdown in Starlight's `docs` collection under a `docs/` subfolder; rule pages, the changelog and the agent setup text are read from the repository's own files by `glob()` collections and rendered in the Starlight layout by routes in `src/pages/docs/`. One stylesheet holds the colour and type tokens for the landing page and the Starlight theme.

**Tech Stack:** Astro 7.4.x, `@astrojs/starlight` 0.43.x, Node 24, npm, `@fontsource` font packages, Node's built-in test-free check script (`node scripts/check-dist.mjs`).

**Spec:** `docs/superpowers/specs/2026-11-26-docs-site-design.md`

## Global Constraints

- English only; no mention of any company or private tooling; Conventional Commits, no attribution lines.
- Do not change Rust code, `docs/rules/*.md`, `docs/agent-setup.md`, `CHANGELOG.md`, `README.md` or the plugin; a mismatch between a document and the code is reported in the PR body.
- Every statement about behaviour is checked against the code (`src/`) or the v0.2.0 binary; untested platforms and hosts are named as untested (macOS binaries, Linux arm64; hosts other than Claude Code and Codex CLI).
- The docs say shellwise is a guard against careless mistakes, not a security boundary.
- Maintainer documents (`docs/design.md`, `docs/spikes.md`, `docs/superpowers/`) are neither published nor linked.
- `site: 'https://borcioo.github.io'`, `base: '/shellwise'`; every internal link in Markdown and `.astro` files carries the base. Sidebar `link` and `slug` entries omit it: Starlight adds it.
- As built, the plan's Tasks 1 and 2 landed in one commit; the check compares rule names exactly (not counts), refuses relative links and matches link targets case-exactly; the duplicate title of a rendered repository document is hidden by a rule in `starlight.css`; the landing page shows no release version.
- Dependencies are added with `npm install`, never typed into `package.json`.
- Dark only: no theme switch.
- Run every `npm` command with Node 24 first on `PATH`.

## Review Focus

1. A rule file added on `develop` after this merges: its page, sidebar entry and index row appear with no site change (the check script compares rule names).
2. A rule id with capitals (`rg-follow-L`): URL, sidebar link and index link keep the case and resolve on a case-sensitive host.
3. A link written without the base (`/docs/…`): works in no environment; the link check fails the build.
4. A phone-width viewport: landing header, tables and code blocks scroll inside their box, the page does not scroll sideways.
5. A visitor with JavaScript off: every page's content and navigation render; only search is missing.
